# 1. Introduction
`chiara-speech2text` is a software system for Automatic Speech Recognition (ASR) in users with atypical speech.
- The [project page](https://luca-randazzo.github.io/chiara-speech2text.github.io/) introduces the project (and provides demo videos / screenshots)
- This document provides a technical description of the system and this repo

# 2. System description

## Modules
The system is composed of the following modules:
- `frontend`: webapp to create and curate the datasets used to train the model, including functionalities to:
    - record users' speech
        - users can upload custom words and phrases on which to train the model 
    - edit the dataset, e.g.:
        - edit transcripts
        - listen to- and delete- low quality recordings not suited for model-training
- `model-trainer`: Python notebooks to:
    - import datasets generated by `frontend` module
    - train fine-tuned voice recognition models (based on OpenAI Whisper) using the datasets
- `fine-tuned models`: binary files containing the fine-tuned models (bias, weights, architecture, etc), as output'd by `model-trainer`
- `model-server`: Python webserver exposing services that:
    - (i) accept audio inputs, and
    - (ii) transcribe audios using the `fine-tuned models`  
- `keyboard`: custom Android keyboard to:
    - record user's speech
    - send recorded audios to `model-server`
    - show, edit transcripts returned by `model-server`   
    - deploy transcript exposing a standard Android input-method (keyboard), for seamless use e.g. in Whatsapp
    - provide suggestions for words similar to the recognized ones (using Levenshtein distance)
- `models-evaluator`: Python notebooks to evaluate amd compare performance (e.g. WER) of different fine-tuned models
- `storage`: Google Firebase storage bucket to store audio recordings and transcripts
- `utils`: Python utils to e.g trim audios, migrate data etc

### Fine-tuning process
The image below shows the process which was employed to iteratively fine-tune models for Chiara.
![image info](../assets/images/diagram_fine-tuning.png)

The process can be summarized in the following steps:
1. Luca and Chiara (with help from their father and mother), defined a set of inputs (words / phrases) they deemed useful for Chiara's daily communication (based on what she typically communicates over Whatsapp)
2. Chiara recorded ~1h of her speech for the defined inputs, through the `frontend` module. Audios + corresponding text was stored in a firebase storage
3. Luca cleaned audios (e.g. removed bad recordings) to ensure clean data was available for models-training 
4. A model was fine-tuned using the labeled data (audios + text) from (2) and (3)
5. The fine-tuned model was used to transcribe batch of other available Chiara's audios (i.e. Whatsapp audio messages which Chiara exchanged with Luca over previous years)
6. Luca manually labeled the Whatsapp audios (i.e. generated draft transcripts via the fine-tuned model, listened to the audios and edited the corresponding transcripts to ensure transcripts matched what was said in the audios)
7. The data from (6) was used to fine-tune a new model
8. If the fine-tuned models showed bad performance on specific words, steps (1) and (2) were repeated on such words
9. Steps (6) to (8) were iteratively repeated

At around ~10h of properly labeled data (recordings + transcripts), the system was capable of reliably transcribing Chiara's speech - achieveing WER ~15

# 4. Requirements
- Usage
    - Some coding skills are required to install, deploy, and use this system
- Data
    - ~10h of labeled data are required to start getting acceptable transcription performance (WER ~15)
    - Data recordings must be <30s (due to the limit imposed by the OpenAi Whisper)
    - Data must contain silences and corresponding empty transcripts
- Deployment
    - A GPU is required for fast (<1s) inference (transcription). CPUs generate transcripts in ~8s
    - The system currently requires paid-services (for hosting)
        - Data hosting costs: https://firebase.google.com/pricing
        - [not currently used] Server hosting costs: https://cloud.google.com/run/pricing
